# 2026-10-08 — Closures in the conformance loader (threads stay out)

## Context
The user asked to resume the parked closure-frame item and whether
certificates for closures and thread scheduling could bring those tests
in. Survey: no supported entry ran a closure; 7 corpus entries with
closures were unsupported, 4 supported ones were prepared with "closure
-> named fn".
[DEC] Threads stay unsupported (user's choice): 3 of the 4 thread tests
(`retag_data_race_*`) fail in Miri with a DATA RACE (vector clocks,
`-Zmiri-deterministic-concurrency`), not a Stacked Borrows error; a
schedule certificate could linearise them, but mirlite/OSEA-IR have no
race semantics, so no verdict would match. box-custom-alloc-aliasing is
blocked by custom allocators / dyn, not threads.
[DEC] Closures are loader work, not certificate work: Charon runs
`--monomorphize`, so every closure call is static.

## What Charon gives
[OBS] A closure = a struct of captures + trait-impl methods `call_once` /
`call_mut` / `call` (+ `as_fn`, the `fn`-pointer coercion, + a
`drop_glue`). A call `f(x)` is `Call { func: Trait [TraitImpl{id}, method
idx] }` with tupled args. The closure TYPE records its kind
(`src.Closure.info.kind`, inferred from the expected bound: a closure
passed where `FnOnce` is expected is `FnOnce`); the method of that kind
holds the body, the others forward to it.
[OBS] Miri: the body is the frame `f::{closure#N}` (InstanceKind::Item,
DefKind::Closure); the forwarders are shims (ClosureOnceShim, the reify).

## Changes
- ullbc_ast: trait calls resolve via (impl id, method idx) -> fun id
  (`implTables`); `FrameRole` per function (plain / closureBody
  `{closure#N}` / shim); `UniqueImmutable` borrow -> `.mut` (rustc's
  `Mut { ClosureCapture }`); `PhantomPinned` marks its struct
  (`StructLay.pinned`), `UTy.notUnpin`.
- lowering: a certificate frame opens only for plain functions and
  closure bodies (named `{closure#N}`).
- elab: a `Mut`/`BoxMut` retag of a `!Unpin` pointee becomes `TwoPhase`,
  unprotected (Miri's `from_ref_ty`/`from_box_ty`: SharedReadWrite, no
  access, no protector).
- miri_cert.py: user kinds include `Closure`; `user_fns` includes
  `{closure#N}` for the cross-check.
- stdlite `Box::from_raw`: now RETAGS the new Box (Unique + write), as
  std's `Box(Unique::new_unchecked(raw), alloc)` does in Miri. The plain
  copy missed newtype_(pair_)retagging's real UB; the prepared versions
  only passed through a different UB at the later drop.
- emit: [BUG FIX, found here] a constant-folded `binOp` dropped its place
  operands' READS (`*pb += 1` after `pb` was popped: UB missed, plain code
  too). Folds now copy each place operand first.
