# 2026-10-04 — A Vec shim in the loader

[DEC] (user) Model `Vec` with our own loader shims, not std's real code.
Reasons (2026-10-03/04 discussion):
- Charon gives `Vec` as an opaque type with bodyless methods.
- `--extract-opaque-bodies` translates 222 std functions, but the loader
  first hits a constant (`MAX_SLICE_LEN`) and would also need rustc's
  enum layouts, static data, and run-time memcpy/offset.
- A Miri certificate cannot cover std frames: the pinned Charon (nightly
  2026-06-01, rustc 14210df) and Miri (rustc 4667d75) run different std
  sources (vec/mod.rs differs by 139 lines).
- The Vec tests depend on a handful of Vec behaviours, not on its
  internals.

## What was built

[OBS] Loader type `vecT elem`, laid out as the header `(ptr, cap, len)`
(`vecHeader`). The buffer pointer is raw: `Unique`/`NonNull` are never
retagged. Shims in `stdlite.lean`, each written from the std body at
Miri's toolchain:
- `new`: a dangling pointer without provenance at the alignment; cap 0;
  no allocation.
- `len`, `as_ptr`/`as_mut_ptr`: fn-entry retag of the receiver, then a
  read of the field. `as_ptr` makes no reference (std avoids `deref`
  for exactly this reason).
- `push` (`push_mut`):
  - grow when `len == cap`: new cap = max(2·cap, len+1, min_non_zero_cap);
    `alloc`, then copy the old elements and `dealloc` (Miri's realloc);
  - in-bounds `ptrOffset` to `len`, `ptr::write`, `len += 1`;
  - `&mut *end`.
- `Deref`/`DerefMut`: `subSlice` narrowing to `len`, then a `refSlice`
  retag.
- `vec![..]`:
  - `Box::new_uninit` is an `alloc`;
  - the literal is written through `MaybeUninit`/`ManuallyDrop`/
    `MaybeDangling`, which are now transparent, field projections
    dropped (`transparentField`);
  - `box_assume_init_into_vec_unsafe` is `boxIntoRaw`'s retags plus
    `(ptr, N, N)`.
- Drop: a protected `&mut` retag of the header, then `dealloc` when
  cap·size ≠ 0. There is no slice retag: rustc's drop shim retags only
  types with drop glue.
- Also: `slice::from_raw_parts(_mut)`, `<[T]>::get` (static index,
  in-bounds case only), `<i32 as AddAssign>::add_assign`.

Only the outermost fn-entry retag of each call is emitted. Nested std
calls retag from that fresh tag and cannot affect any other pointer.

[DEC] Length and capacity must be known statically. Growth is decided
by the loader.
[OBS] That needed one tracker change: `LowerSt.heapPtrs`, the places
holding a pointer into a heap block. Pointers from `emitAlloc` count,
and the mark is copied with the pointer, also across casts and offsets.
A write whose last dereference goes through one (`inHeap`) lands in no
local, so it no longer forgets every tracked constant. Without it,
`vec![1]`'s write into its Box lost the Vec capacities.

## Later: String and string literals

[OBS] String literals:
- A new operand `UOperand.str bytes`, parsed from Charon's
  `{"Literal": {"Str": …}}`.
- `str` is parsed as `sliceData u8`, so `&str` is a `u8` slice.
- `materialiseStr` gives a literal a heap block of its own holding the
  bytes (Miri: a global allocation), plus a slice pointer over it with
  the allocation's tag and no retag.
- Assignments materialise literals (`emitAssign`), and so do inlined
  calls' arguments; a shim gets the literal itself.
- Writes to the block are not rejected (Miri: read-only memory, UB).

[OBS] `String` is parsed as `vecT u8` (`String { vec: Vec<u8> }`).
Shims:
- `String::from(&str)` (`to_owned` → `to_vec`): the argument's entry
  retag, an allocation of exactly `len` bytes, `copy_nonoverlapping`,
  then `(buf, len, len)`. The argument must be a literal: its length is
  the capacity.
- `String::len` and `<String as Deref>` reuse the Vec shims; there is
  no inherent `String::as_ptr`, the call goes through `Deref`.
- `str::as_ptr` is `sliceAsPtr`.

[OBS] A bug the new witness caught: the Vec drop had copied the Box
drop's "past Miri's UB point" poison, which fires whenever the
certificate's events are all consumed. Box drops are certificate events
and Vec drops are not, so `drop(s)` before the UB was poisoned (a missed
UB). Now the poison is only the fallback for a drop that cannot be
lowered (runtime capacity).

[OBS] Results:
- drop_after_sharing (split-out) passes.
- New witnesses: string_drop_use_after_free (UB, freed; reason as Miri)
  and str_literal_bytes (ok; the certificate checks the byte read at
  run time).
- No other verdict moved.
- Corpus 170/0/0/20 of 190; --osea 170; --layouts 170; units 32 + 138;
  audit unchanged.

## Later: allocation sizes were wrong (found by the units rename)

[OBS] `LStmt.alloc`'s operand counts POINTEES of the destination
(mirlite allocates `n · |pointee|` bytes), not bytes; it is now named `n`.
The `B`-suffix rename had called it `sizeB` for a moment. Three call
sites passed bytes for typed pointees:
- `vecGrow`: `newCap · size` for a `*mut T`, i.e. 64 bytes instead of
  16 for a `Vec<u32>` of capacity 4;
- `materialiseStr` and `String::from`: `n` for a pointer to an `n`-byte
  array, i.e. n² bytes.
No test noticed, because none touched the extra space.

Two Miri-verified witnesses were added first and failed (missed UB)
before the fix:
- vec_capacity_bounds: `p.add(5)` after one push; Miri reports that the
  allocation is only 16 bytes;
- str_literal_bounds: `"hi".as_ptr().add(3)`; the allocation is 2 bytes.
Both pass after it, with reasons as Miri.

[OBS] The same pass fixed stale cell-model comments:
- `uSize` is a LEAF count, sizing `freezeMask` (one bit per leaf, which
  `mirlite.maskBytes` spreads over the bytes); the mask itself was right;
- `AllocLen`: the allocation covers `n · |β|` bytes;
- the enum docs: an 8-byte discriminant;
- the stdlite header: `alloc` allocates bytes;
- g12's doc: the stride is 16 bytes.
Corpus 172/0/0/20 of 192.

## Later: push_str, format!, assert_eq! on strings

[DEC] (user) `format!` as a narrow, checked model (alternatives costed:
tracking heap contents statically, a prep rewrite, std's real fmt code).
[OBS] The pieces:
- `push_str`: entry retags, growth as `reserve` (`grow_amortized`), then
  an in-bounds offset and a byte copy.
- `.into()` (`<&T as Into>::into`) is `String::from`, now for any
  `&str` whose length the tracker knows: a literal's length is a
  pseudo-field (`lenField`), copied with the slice and its reborrows.
- `<String as PartialEq<&str>>::eq`: entry retags, then slice
  reborrows. Unequal lengths are false with nothing read; equal lengths
  compare every byte at run time (`Eq` and `BitAnd` binOps).
- `format!` = `Argument::new_debug`/`new_display` + `Arguments::new` +
  `alloc::fmt::format` + `must_use`:
  - an `Argument` is (erased pointer, a word indexing `fmtArgTys`: type,
    Debug, and the root key it points at);
  - `Arguments` is (a word indexing `fmtSpecs`, the template parsed when
    loading; erased args pointer);
  - `format` emits Debug/Display's retags and reads for integers,
    `String`, `&str`, `Vec<int>` and references to them, and writes the
    output into a fresh `String` sized to its length.
- Shapes are checked when the program runs (`emitAssume`, a new verdict
  `assumeFailed`, never a program verdict): no Debug string byte needs
  escaping, and an integer of unknown value has one digit. Checked in
  the scratchpad: `vec![12]` and `"a\"b"` both report a failed
  assumption.
- Also: resolveKey fuel 8 → 32 (the field chain through two inlined
  helpers needed more), and the bodyless-function message prints the
  full path.

[OBS] disjoint_mutable_subborrows passes. Its assert branch is a
run-time certificate check, so the model's formatted bytes equal
`"hello world" [0, 1, 2, 4]`.
Witnesses:
- format_through_popped_ref: UB, retag of the header (Miri raises inside
  core::fmt, so verdict only);
- push_str_realloc_use_after_free: UB, freed;
- format_display_debug: ok; its output bytes are checked by the
  certificate.
[OBS] A limit: statements expanded from std macros (`format!`, `vec!`)
carry the macro's own source lines (Charon gives no call site), so UB
