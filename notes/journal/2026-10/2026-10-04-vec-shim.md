# 2026-10-04 — A Vec shim in the loader

[DEC] (user) Model `Vec` with our own loader shims, not std's real code.
Reasons (2026-10-03/04 discussion):
- Charon gives `Vec` as an opaque type with bodyless methods.
- `--extract-opaque-bodies` translates 222 std functions, but the loader
  first hits a constant (`MAX_SLICE_LEN`) and would also need rustc's
  enum layouts, static data, and run-time memcpy/offset.
- A Miri certificate cannot cover std frames: the pinned Charon (nightly
  2026-06-01, rustc 14210df) and Miri (rustc 4667d75) run different std
  sources (vec/mod.rs differs by 139 lines).
- The Vec tests depend on a handful of Vec behaviours, not on its
  internals.

## What was built

[OBS] Loader type `vecT elem`, laid out as the header `(ptr, cap, len)`
(`vecHeader`). The buffer pointer is raw: `Unique`/`NonNull` are never
retagged. Shims in `stdlite.lean`, each written from the std body at
Miri's toolchain:
- `new`: a dangling pointer without provenance at the alignment; cap 0;
  no allocation.
- `len`, `as_ptr`/`as_mut_ptr`: fn-entry retag of the receiver, then a
  read of the field. `as_ptr` makes no reference (std avoids `deref`
  for exactly this reason).
- `push` (`push_mut`):
  - grow when `len == cap`: new cap = max(2·cap, len+1, min_non_zero_cap);
    `alloc`, then copy the old elements and `dealloc` (Miri's realloc);
  - in-bounds `ptrOffset` to `len`, `ptr::write`, `len += 1`;
  - `&mut *end`.
- `Deref`/`DerefMut`: `subSlice` narrowing to `len`, then a `refSlice`
  retag.
- `vec![..]`:
  - `Box::new_uninit` is an `alloc`;
  - the literal is written through `MaybeUninit`/`ManuallyDrop`/
    `MaybeDangling`, which are now transparent, field projections
    dropped (`transparentField`);
  - `box_assume_init_into_vec_unsafe` is `boxIntoRaw`'s retags plus
    `(ptr, N, N)`.
- Drop: a protected `&mut` retag of the header, then `dealloc` when
  cap·size ≠ 0. There is no slice retag: rustc's drop shim retags only
  types with drop glue.
- Also: `slice::from_raw_parts(_mut)`, `<[T]>::get` (static index,
  in-bounds case only), `<i32 as AddAssign>::add_assign`.

Only the outermost fn-entry retag of each call is emitted. Nested std
calls retag from that fresh tag and cannot affect any other pointer.

[DEC] Length and capacity must be known statically. Growth is decided
by the loader.
[OBS] That needed one tracker change: `LowerSt.heapPtrs`, the places
holding a pointer into a heap block. Pointers from `emitAlloc` count,
and the mark is copied with the pointer, also across casts and offsets.
A write whose last dereference goes through one (`inHeap`) lands in no
local, so it no longer forgets every tracked constant. Without it,
`vec![1]`'s write into its Box lost the Vec capacities.
