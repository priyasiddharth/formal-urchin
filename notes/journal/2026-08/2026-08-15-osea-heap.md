Design points, all about matching mirlite's event order exactly:

[FACT] `Stmt.alloc` compiles as: dst-root Alloc (mirlite's
`preparePlaceAssign` runs FIRST, before the length read) → `AllocN`/
`AllocDyn` (heap `M.own`) → `RStore` of the pointer (the `useMut` of
`finishPlaceAssign`). Keeping the root-alloc before the heap-alloc is
what keeps both machines' bump allocators address-identical.

[FACT] A runtime allocation length is a real SB read: mirlite's
`readAllocLen .fromPlace` does `M.read` on the length cell, so
`AllocDyn` performs the same read *inside the instruction* (register →
ptr → M.read 1 → mem word → allocate n·typeSize). Undef/non-word length
errs on both machines.

[FACT] `Dealloc` takes the *loaded* pointer register: the compiler
emits `Load` (= mirlite's read of the pointer cell) then `Dealloc`,
which checks `offset ≠ 0` against the stored value, calls
`M.dealloc base size tag`, and `removeRange`s the cells. The allocs
table is still NOT in oseair.Mem — dealloc uses the ptr value's own
size field, exactly as mirlite does; only fromExposed's `resolveAddr`
will need the table.
