# The copy leaf: the memory relation was missing a direction

[FACT] `copy_local_local_simulation` (copy.lean, commit f2b7bc8) closes
the copy leaf's core: `dl := sl` between two bound locals. Every
statement kind in `CoreProg` now has a working core. The permission side
was easy — both machines do the SAME two events in the same order (SB
read over the source block, then a write over the destination block),
and both transports already existed. The target does it in ONE `Memcpy`,
so the fragment is a single instruction.

[FACT] The real content was the VALUES, and it exposed a genuine gap in
the invariant. `SourceMemSim` constrains the target only where the
SOURCE has a cell. That suffices for writes, which carry their own
values, but not for reads: both machines' `readWordSeq` return
`undef`/`Val.Undef` at an absent cell, so copying out of a range the
source never wrote would have required relating `undef` to whatever the
target happened to hold there — unprovable, and not because the
compiler is wrong. `TargetAbsentSim ρa mem_mir mem_osea` (absent in the
source ⟹ absent in the target) closes exactly that hole and nothing
more; `readWordSeq_sim` is its payoff and the heart of the copy proof.
It is now a `CompilerInv` conjunct, re-established by all four
previously-closed regimes via `TargetAbsentSim.writeWordSeq_extend` (in
regime D through the spine's memory-preservation equation).

[FACT] Test coverage for copy, checked before proving (it is the
best-covered rvalue in the project, so the risk was always in the
invariant, never in the machine semantics being wrong):
- `src/obseq3/compile_tests.lean`: 17 of 36 differential tests exercise
  `.copy`, including `d6_tuple_copy` (multi-cell `Memcpy`), deref and
  nested-deref reads, and projected-field reads.
- `src/obseq3/tests.lean`: 5 of 20 unit tests.
- The Miri corpus: `.copy` is the lowering of every Rust `use` operand
  (`lowering.lean`'s default assignment case), so nearly all 77 passing
  conformance tests run copies through both machines.

[FACT] CORRECTION to an earlier claim in this session, now fixed in the
audit and in 2026-08-21-regime-c.md's [OPEN]: "one generalization over
an opaque base run closes five sorried regimes" was WRONG. Tracing the
lowerings shows three different shapes:
- PROJ-OVER-DEREF and REF-NONLOCAL-DST do reduce to regime C's
  composition over an opaque base run.
- PROJ-NESTED stacks TWO borrow/die pairs, so it needs n-fold
  cancellation.
- `const_write_deref_nonspine` and COPY-NONLOCAL-SRC need a
  READ-flavoured sibling of BRIDGE 1: the deref lowering emits its inner
  place's cleanup itself, so the chain is `Borrow(Shared) ; Load ; Die`,
  and the keystone cancels Mut-and-write only.
Silver lining from the same trace: `p = &x.f` (REF-NONLOCAL-SRC over a
bound local) is CHEAPER than assumed — it compiles to `Borrow ; RStore`
with a nonzero offset and no cleanup `Die` at all, i.e. structurally the
ref core already proved.
